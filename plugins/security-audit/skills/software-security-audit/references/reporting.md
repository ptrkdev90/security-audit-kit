# Reporting contract

Write the requested-language narrative from the report template. Summarize scope and
source-only/runtime limits before findings. Separate confirmed application vulnerabilities,
dependency advisories, control gaps/hardening, evidence gaps, suspicions, accepted risks,
fixed and bounded refutations. Counts refer to records, not scanner alert totals.

Populate the shared report narrative with executive outcome, scope, threat model,
limitations, remediation/retest and optional compliance assessment. Reconcile every ID,
kind, severity and status against findings.json. List failed/unavailable tool runs and
blocked runtime checks visibly, including in the executive outcome. Keep conditional
impact language for unverified candidates. Do not assert all XSS absent from sink searches.

Register exact evidence and limits; include upstream defenses and variant review. Recheck
snapshot at closure and re-review changes. Keep accepted risk open until a supplied owner
decision and review trigger; call a fix verified only at the new snapshot after retest.

Templates control layout only. Preserve evidence, coverage, contradictions and missing
information across formats. Draft/Final is document state, not approval or audit certainty.
Use no invented identities or signatures. The final response names durable paths and
states which exports were requested, produced and visually checked. Structure validation
checks consistency, not factual truth. Never finalize untouched starter template prose.
