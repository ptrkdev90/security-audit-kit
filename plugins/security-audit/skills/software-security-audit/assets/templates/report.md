# Software security audit — actual scope

## Outcome
State key confirmed risks and the decisions needed. Do not claim certification.

## Snapshot and scope
Commit, dirty state, dates, environments, exclusions and authorization boundaries.

## Architecture and threat model
Assets, actors, trust boundaries and high-risk flows.

## Confirmed findings
| ID | Severity | Component | Impact | Evidence | Remediation |
|---|---|---|---|---|---|

## Unresolved candidates and accepted risk
Retain prerequisites, missing evidence and explicit owner decisions.

## Coverage and tool execution
Reference coverage.json and tool-runs.json, including failures and ignored paths.

## Limitations
List blocked checks, missing runtime/cloud access, unsupported ecosystems, stale feeds
and source-only conclusions. Avoid unqualified claims that the project is secure.

## Remediation priorities and retest
Order by verified impact and exposure. Assign next verification, not invented deadlines.
