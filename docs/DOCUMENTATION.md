# Technical documentation profile

This toolkit publishes a security review, not an operating manual. It applies editorial
principles deliberately; it does not declare conformity with documentation standards.

| Reader | Needs | Report location |
|---|---|---|
| Project owner | Verified risks, decisions, blocked checks | Executive outcome and limitations |
| Engineer | Source locations, paths, defenses, exact retest | Findings and evidence |
| Reviewer | Snapshot, scope, confidence, contradictions | Coverage, evidence and provenance |
| Compliance owner | Evidence owner/period, missing records | Optional readiness matrix |

Use consistent terms, active verbs, concise sentences, meaningful headings and accessible
captions. Detailed code excerpts must be sanitized. Every change to the audited snapshot
requires a documented new evaluation; every report edit gets a report-version/history entry.
Use a glossary for acronyms and distinguish Draft/Final from review/approval.

For English, an explicitly requested ASD-STE100 profile should name its issue and use an
authorized full copy/checker. Plain wording alone is not conformance. German reports follow
plain German conventions; the English controlled vocabulary is not mechanically translated.
See [standards applicability](STANDARDS.md) for scoped use and primary-source references.
